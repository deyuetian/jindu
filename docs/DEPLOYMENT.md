# 部署与数据保存

需要 Linux 服务器、Docker Engine 和 Docker Compose v2。统一更新工具另需宿主机 Python 3.10 或以上。生产环境需要 HTTPS 入口，可以使用现有反向代理或 Cloudflare Tunnel。Cloudflare 不是必需依赖。

程序使用一个镜像，分别运行 `web` 和单实例 `worker`；SQLite 和附件保存在同一个本机数据目录。没有 Redis 或独立数据库服务。

下载并解压发行源码包，或检出对应版本的 Git 标签后，在该目录执行：

```sh
cp .env.example .env
# 编辑 .env 中的网站地址和账号名
docker compose build web
docker compose run --rm --no-deps init
docker compose up -d web worker
```

初始化只适用于空目录，会生成一条长随机密码，保存在 `private/login.txt`。不会在终端输出密码。生产环境先将 `JINDU_ORIGIN` 改为完整的 HTTPS 网址，例如 `https://planner.example.com`。设置页保存 AI 接口和采集来源后，后台自动运行。

默认只监听主机的 `127.0.0.1:8788`。反向代理指向这个地址，并保留浏览器访问的 `Host`。若反向代理运行在另一个容器中，应显式配置共用网络和目标服务；不要把代理容器的 `127.0.0.1` 当成宿主机。正式域名与配置中的 `origin` 必须一致。

`http://localhost:8788` 仅用于本机试用。更改端口时也要对应修改 `.env` 中的 `JINDU_ORIGIN`。初始化之后，账号、网址和路径以 `private/config.json` 为准，修改 `.env` 不会重写已有配置。

## 程序、数据与密钥

| 位置 | 内容 | 处理方式 |
|---|---|---|
| 镜像 | 前端、后端与运行依赖 | 可重新构建 |
| `data/` | 完整 SQLite、附件及最近三份业务备份 | 迁移时完整保留 |
| `private/config.json` | 登录校验值、加密主密钥和运行配置 | 私密保存，随数据迁移 |
| `private/login.txt` | 初始登录信息 | 仅管理员保管 |

AI 密钥和日历订阅凭据用配置中的 `masterKey` 加密。迁移时必须保留原密钥，否则已有密文不能解密。不要公开 `private/`、`data/` 或完整迁移备份。

网页中的业务备份包括业务记录、历史及附件，保留最近三份；它不包含完整运行配置、账号、AI 密钥或所有运行状态。更换服务器和程序升级需要完整保存数据目录及私密配置，不能仅依靠网页下载的业务备份。统一更新工具会另做完整备份，详见[升级与恢复](UPGRADING.md)。

首次安装后请保留整个安装目录。不要把 `private/config.json` 当作可以重新生成的缓存。更改公网网址时同步修改其 `origin` 并重启当前部署；现有日历订阅也需更新地址。更改账号或密钥属于另一次管理操作，不是日常升级步骤。

## 运行状态

设置页显示程序版本、后台心跳、备份状态和长时间运行的任务。后台心跳每 15 秒更新，超过 90 秒会提示异常；备份超过 36 小时未成功会提示检查。任务超过 15 分钟只作提醒，不会自动取消。`/api/health` 用于网页存活检查，详细状态位于需要登录的 `/api/health/details`；网页存活不代表后台或 AI 服务正常。
