# 使用说明

## 岗位助手

在“个人条件”填写各段学历、政治面貌、奖项、任职、工作或实习经历和证书。专业按本人对应的门类、一级学科/专业类、具体专业核对，不把本科专业与硕士学历拼成一个资格。

可以说“筛选这个选调公告的岗位并整理报名材料”，附官方公告链接；也可以指定“公告收集”里的完整标题。助手只处理本次指定的公告，下载其可读取附件，先筛专业候选行，再核对通用资格与每岗要求。对已经分析过的公告，可以直接询问岗位、条件或材料，不必重复分析。

公告详情分别展示通用资格、可展开的岗位要求、申请流程、时间节点和原文附件。共用的投递步骤与材料只列一次，岗位中的特殊要求单独保留。岗位卡片注明来源公告；岗位表结果保留真实岗位代码、附件、工作表和行号，表格序号不冒充岗位代码。下载的 Excel 按“已核查条件满足、待补充或核对、有不满足条件”分表，并启用筛选菜单。原表内容保留供复核；筛选表不代表报名审批结果。

`backend/recruitment-skill.md` 是随应用发布并实际载入模型请求的技能说明；`backend/job_workbooks.py` 负责表格及结果导出，`backend/job-tables.ts` 负责岗位行初筛，`backend/recruitment-agent.ts` 负责对话流程。运行环境包含 Python、openpyxl、xlrd、python-docx、pypdf。旧版 DOC 由镜像内的 LibreOffice Writer 无界面组件转换为 DOCX，再读取段落和表格；转换使用独立临时目录，禁用宏和外链更新，超时结束并保留原件。宿主机无须安装办公软件。

Excel 支持多工作表、多行表头和已合并单元格，读取 `.xlsx`、`.xlsm`、`.xls`；ZIP 内支持上述表格、PDF、DOC、DOCX 和文本。公式仅取文件已保存结果并标注复核；扫描 PDF、受保护或损坏的文档、未识别表头、失败或超限附件保留待核对。没有读完时不会声称全部岗位可报。

高校就业网页另行加载的岗位明细与正文一起保存，保留学历、专业、人数、地点、职责和任职要求。岗位分析逐行进行；遗漏的行会留下待核对记录。公告简介采用介绍形式，个人条件结论另列；选调标题保持原样，其他招聘标题简化展示，原始标题始终保留。

原文明确不限专业且学历范围相符时，专业条件判为符合；政治面貌、经历和其他资格仍分别核对。旧结果在展示时使用当前规则复核，直接询问已保存的岗位和材料不会重跑公告分析。重新分析从本次进度开始；成功分段可继续，连续失败有重试次数限制。

专业匹配与关注状态分别管理。旧版手动选择的“拟投递”继续显示为“关注”，无需重选或批量改写历史记录。“关注”由使用者选择或取消，重新分析保留已选进度与备注。早期版本自动标记的“收藏”按未选择显示，不会批量转成关注；已经记录的准备材料、已报名等进度保留。岗位卡片简述招收专业，完整专业目录与匹配依据放在详情的展开项中。地区采用完整省级名称，原文证据保持原样。

导航与岗位筛选显示当前“关注”数量，仅统计使用者明确选择、尚未归档且属于当前分析结果的岗位。准备材料、已报名等后续进度单独保留，不混入此计数。

公告概览按面向对象、学历、招聘方向、地点、专业范围与报名安排展示；专业目录映射和个人是否符合放在资格详情。申请步骤按有据日期排列，缺少日期的步骤按招录阶段归位；材料独立列出。校内办公室盖章、自助机和办公时间等服务信息留在原件中，官方要求提交的审核盖章推荐表仍保留。旧分析结果也应用这些展示规则，无须为整理版面全量调用模型。

在岗位卡片或详情点击“加入日历”，勾选所属公告已公布的日期。日程名称使用“公告名称 · 节点”；同一公告下的多个岗位共用一份日历，重复点击打开已有安排，不覆盖手动修改。可选择自动跟进日期；面试及以后仍需本人明确声明通过后开启。没有可用日期时，可前往公告的时间节点手动补充。原有手机和 Outlook 订阅继续读取同一份日历。 时间节点按日期和时刻排列；同一环节的“网上报名/报名”等同义节点自动合并，调剂、改报、不同批次及冲突时间分别保留。旧公告在读取时应用同样规则，无需重新调用 AI。公告的时间节点入口使用同样的阶段规则；待公布日期可以留空保留，已填日期可以先加入。导入时手动改过的日期受保护，自动跟进不会覆盖。

专业层级示例依据[中国农业大学学术学位学科专业目录](https://gradsch1.cau.edu.cn/art/2025/4/9/art_40279_1062390.html)。公告使用地方专门目录时仍按该公告核对。表格的读取与筛选设置使用 [openpyxl](https://openpyxl.readthedocs.io/en/stable/filters.html)；后台实际筛选数据后生成工作簿。

## 限额与核对

“无上限”取消每日请求次数限制，仍保留网络超时、有限重试和单次输出边界。首次升级不会自动替用户开启。修改个人档案会用已有依据重新核对，不会自动重跑全部历史公告；旧公告需要新增条件提取时，可在详情里重新分析。

复杂资格条款、不同称谓的等价关系和缺少依据的条件保留为“待核对”。条件检查依据用户填写的资料和公告原文，不能代替招录单位认定。自动采集支持可公开读取的页面；需要登录、特殊接口或前端动态加载的来源可能需要单独适配。
